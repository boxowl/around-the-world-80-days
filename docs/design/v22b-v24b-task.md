# V2.2b + V2.4b: долговечный v2-зачёт и паспорт

Старт: 2026-11-10. Ветка `feature/v22b-v24b-persistence`, worktree `/private/tmp/mobile-v22b-v24b`, база `bce8f11`. Источники правил: `docs/design/v2-product-decisions.md`, `docs/design/v22b-v24b-dependency-map.md`, `docs/SPEC.md` (календарь v1), `docs/design/v24b-passport-storage.md`.

## Цель

Добавить отдельный v2-агрегат с C-lite namespace в Room v4 и восстановление дневных шагов/расчётных метров/штампов паспорта. Ни один существующий v1-пользователь не меняет прогресс после обновления.

## Границы

Разрешены: `ExpeditionDatabase.kt` только для четырёх новых v2 entity/DAO и аддитивной `MIGRATION_3_4`; новые файлы `expedition/credit/*` и `expedition/passport/*` для конвертации, хранилища и транзакционного восстановления; соответствующие unit/androidTest; этот документ и `TODO.md`. v1 `ExpeditionRepository`, существующие таблицы и их DAO не изменять по смыслу. Не трогать route/path/scene/health, UI, навигацию, пороги, Gradle, подпись. Подключение v2 к production UI/синхронизации — следующий отдельный блок, чтобы миграция и восстановление были проверены изолированно.

## Критерии готовности

1. Шаги дня переводятся в целые расчётные метры `floor(steps × strideMillimeters / 1000)` с проверкой переполнения; 0 отличается от отсутствия дня. Поздняя замена исправляет и исходные шаги, и метры; повторы идемпотентны.
2. `daily_credit` и паспорт изолированы по `expeditionSeq`; две экспедиции с одинаковой датой не смешиваются. Новый явный старт атомарно завершает старую ACTIVE, сохраняет её строки и начинает новый паспорт со стартовым штампом. Не более одной ACTIVE.
3. При холодном старте восстанавливаются `CreditLedger` и `PassportSnapshot`; книжный итог = сумма расчётных метров ×20, без второго накопителя. Базовая линия паспорта и новые штампы пишутся в одной транзакции; откат не отзывает штампы и не меняет старые даты. Неизвестные даты остаются NULL.
4. Миграции 1→2→3→4 и 3→4 сохраняют все v1-строки и открытые дневники. Нет destructive fallback. Room schema validation, unit, assemble, lint и доступные instrumentation зелёные.
5. Отдельный строгий review миграции, арифметики, одной ACTIVE и межмодульных границ перед PR. Физическая P02/F02/Q01 остаётся открытой.

## Порядок

Конвертер с unit-тестами → entity/DAO/миграция с androidTest → хранилище и двухпроходный паспорт с тестами → строгий review → локальные проверки → push и PR → обновление TODO по факту. Не подменять незавершённую реализацию готовностью всей v2-цепочки.
