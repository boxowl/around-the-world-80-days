# F11b — удаление локальных данных

- Цель: дать пользователю явный сброс всех локальных экспедиций v1/v2, дневника, штампов и настроек из обеих активных страниц настроек.
- Ветка/worktree: `feature/f11b-clear-local-data`, `/private/tmp/mobile-f11b-clear-local-data`.
- Границы файлов: новый UI control в `expedition/`, `ExpeditionPanel.kt`, `V2JourneyScreen.kt`, этот task doc, затем `TODO.md`. Не менять Room schema/repository, F01 AtomicFile API, Health Connect, расчёты и маршрут.
- Основа: `expedition.db` (Room v1/v2) и `files/expedition-v1.json` (F01 recovery copy). Ручное удаление одной БД опасно: оставшаяся F01-копия импортируется снова. Системный `ActivityManager.clearApplicationUserData()` удаляет приватные данные приложения целиком и отзывает его разрешения ([Android API](https://developer.android.com/reference/android/app/ActivityManager#clearApplicationUserData())). Данные Health Connect других приложений не удаляются этим вызовом.
- Защита: кнопка открывает предупреждение; подтверждение доступно только после ввода `DELETE` латиницей. Отмена не вызывает сброс. При отказе системного API показывается ошибка; успешный запрос не называется завершённой очисткой до повторного запуска.
- Готово, когда: control доступен из v1 и v2 настроек; на эмуляторе отмена сохраняет тестовые данные, подтверждение удаляет и Room, и F01-копию, после перезапуска нет повторного импорта; сборка, JVM-тесты, lint, instrumentation, CI и независимое строгое ревью зелёные. Эмулятор не закрывает физическую приёмку P02/F02/Q01.
- Цикл: изучить все хранилища и системный API → UI/control → локальные проверки и сценарий на эмуляторе → строгое read-only ревью → PR/CI → слияние и передача.
