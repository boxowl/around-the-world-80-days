# Вокруг света за 80 дней

Android-приложение на Kotlin и Jetpack Compose: шаги из Health Connect продвигают путешественника по маршруту Жюля Верна, открывают остановки и записи дневника. Прогресс хранится локально. Для текущей альфы не нужны аккаунт, сервер или постоянный GPS.

## Что работает сейчас

В `main` находится альфа **0.9.1** (`versionCode 10`, Android 9+, `minSdk 28`, `targetSdk 36`). Она включает онбординг с выбором режима и темпа, чтение шагов из Health Connect, участок Лондон → Суэц, непрерывную сцену путешествия, карту первого участка, события и устойчивый дневник. Экспедиция, дневные итоги и состояние дневника сохраняются в Room; схема v3 поддерживает миграции v1→v2→v3. Диагностика шагов доступна в настройках.

Код, сборка и сценарии с синтетическими данными проверены на эмуляторе Pixel 7 / Android 16. **Настоящие шаги на физическом телефоне и браслете ещё не проверены.** Поэтому [P02/F02/Q01](TODO.md) остаются открытыми, а результат эмулятора не считается аппаратной приёмкой.

Для новой версии маршрута в `main` уже есть измеренная геометрия `RouteDatasetV1`/`RouteMeasure`, чистый расчёт зачёта `CreditLedger` (1 подтверждённый реальный км = 20 книжных км, без дневного лимита) и отдельный debug-прототип глобуса. Это основа будущей v2, а не подключённая к реальным шагам и Room новая экспедиция. Источник реальных метров и жизненный цикл повторных v2-экспедиций ещё требуют решения; см. [карту зависимостей](docs/design/v22b-v24b-dependency-map.md) и [варианты жизненного цикла](docs/design/v2-expedition-lifecycle.md).

## Сборка и запуск

Нужны JDK 17 или 21, Android SDK Platform 36 и Build Tools 35.0.0. Укажите SDK через `ANDROID_HOME` или в локальном `local.properties` (`sdk.dir=/абсолютный/путь/к/sdk`). Этот файл не коммитится.

```sh
./gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
# После подключения телефона с USB-отладкой:
./gradlew :app:installDebug
```

Debug APK после сборки: `app/build/outputs/apk/debug/app-debug.apk`. На настроенном Mac эмулятор запускается через `./scripts/run-emulator.command`; подробности и границы проверки — в [docs/EMULATOR.md](docs/EMULATOR.md). При наличии локального кэша зависимости можно собирать с `--offline`. CI собирает APK и выполняет проверки из [Android workflow](.github/workflows/android.yml).

Для проверки настоящих шагов используйте [протокол физического телефона](docs/HEALTH_CONNECT_TEST.md): сначала зафиксируйте модель, Android, источник Steps и разрешения, затем результаты сценариев. Данные часов доступны приложению только если их источник передаёт Steps в Health Connect; прямого Bluetooth-подключения к браслету нет. Локальный `dist/` содержит установочные сборки и видео испытаний, намеренно не отслеживается Git и не является частью исходников.

## Устройство проекта и документы

- `app/src/main/` — приложение, Room v3, Health Connect, v1-путешествие и чистые модели геометрии/зачёта v2.
- `app/src/debug/` — демонстрационные экраны и синтетические сценарии; их данные не считаются настоящими шагами.
- [TODO.md](TODO.md) — актуальные статусы, зависимости и ближайшие решения.
- [docs/SPEC.md](docs/SPEC.md) и [docs/ROUTE.md](docs/ROUTE.md) — правила v1 и маршрут; нельзя менять пороги или календарь по предположению.
- [docs/F02_VERIFICATION.md](docs/F02_VERIFICATION.md)–[docs/F06_VERIFICATION.md](docs/F06_VERIFICATION.md) — проверки включённых в `main` функций.
- [docs/design/](docs/design/) — контракты v2, открытые вопросы и материалы художественной приёмки.

Одна самостоятельная фича ведётся в отдельной ветке и PR. Миграции, расчёты и интеграция Health Connect требуют отдельной строгой проверки. Ключи подписи, токены, локальные настройки SDK и debug APK не коммитятся.
