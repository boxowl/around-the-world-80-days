# V2.4g — записи глав в карточках карты v2

Старт: 2026-11-12. Ветка `feature/v24g-map-narrative`, worktree `/private/tmp/mobile-v24g-map-narrative`, база `43156ca`. Источники: `TODO.md`, `docs/SPEC.md`, `docs/ROUTE.md`, `docs/F06_VERIFICATION.md`, `GlobeStopCardsV1.kt`, `PassportV1.kt`.

## Цель

Вернуть чтение повествовательных записей в карту v2 без отдельной вкладки дневника. Первый самостоятельный срез — девять коротких записей стартового Лондона и финишей восьми глав. Они привязаны к сохранённым штампам данной v2-экспедиции. Откат шагов не скрывает уже открытую запись. Будущая запись закрыта; на промежуточных endpoint-карточках честно указано, что записи главы пока нет. Старый дневник v1 и его прочитанность не переносим в новую экспедицию.

## Границы

Разрешены новый чистый `expedition/globe/V2MapNarrative.kt`, его JVM-тесты, точечный вывод в `V2JourneyScreen.kt`, один instrumentation-тест, этот документ и `TODO.md`. Не менять `FIRST_LEG`, `unlocked_diary`, Room/миграции, Health Connect, `CreditLedger`, `PassportV1`, `RouteDatasetV1`, измеренную геометрию, пороги и правила календаря. Не обещать весь объём 35+ событий/наблюдений из черновика ROUTE.

## Критерии

1. Девять стабильных записей привязаны к девяти `StampId` и соответствующим `GlobeStopCard` без новых числовых порогов. `london#1` и `london#2` различаются.
2. Наличие записи берётся из `PassportSnapshot.granted.containsKey(stamp)`, а не из текущей позиции или browse. Неизвестная дата штампа не закрывает запись; чужая v1-история не подмешивается.
3. На карте видны текст открытой записи или статус «пока закрыта»; на карточках без записи статус «записи пока нет». Тексты — краткая собственная адаптация событий из `docs/ROUTE.md`, без цитат и сомнительных конкретных фактов.
4. Unit-тесты покрывают девять связей, отсутствие данных, откат и два Лондона; instrumentation проверяет стартовый Лондон и закрытый Суэц на синтетической экспедиции. Полный assemble/unit/lint/release compile/emulator instrumentation, строгое read-only ревью интеграции, CI и merge. Физические P02/F02/Q01 остаются отдельно.

Порядок: модель/тексты → тесты → UI → эмулятор → строгое ревью → PR/CI/merge.
