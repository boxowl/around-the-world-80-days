# V2.4f — карточка выбранной остановки на карте v2

Старт: 2026-11-12. Ветка `feature/v24f-stop-card-detail`, worktree `/private/tmp/mobile-v24f-stop-card-detail`, база `4bdd4d1` после PR #35. Источники: `docs/SPEC.md`, `GlobeStopCardsV1.kt`, `RouteDatasetV1.kt`, `V2JourneyScreen.kt`.

## Цель

На вкладке «Карта» можно выбрать одну из 25 endpoint-остановок и прочитать её название, главу, транспорт прибытия, измеренный порог и честное состояние «достигнута/впереди». Выбор карточки остаётся визуальным и не изменяет сохранённый прогресс, паспорт или просматриваемую позицию глобуса.

## Границы

Разрешены новый `expedition/globe/V2StopCardDetails.kt` для чистого форматирования/состояния, его JVM-тесты, точечный UI в `V2JourneyScreen.kt`, один instrumentation-тест, эта задача и `TODO.md`. Не менять Room/DAO, Health Connect, CreditLedger, GlobeStopCardsV1, RouteMeasure/RouteDatasetV1, календарь, паспорт, правила открытия, debug и Gradle. Перенос дневника в карту — отдельный блок.

## Критерии

1. Все 25 карточек доступны в порядке маршрута с отличимыми `london#1` и `london#2`; выбор и содержимое доступны TalkBack. Не дублировать пороги и координаты, использовать готовый `GlobeStopCardsV1`.
2. Состояние карточки пересчитывается из подтверждённого `totalBookMeters`; визуальный browse прошлого его не меняет, откат шагов честно меняет «достигнута/впереди». Порог показывается как книжные км, транспорт стартовой карточки не выдумывается.
3. Локальное состояние выбранной карточки сохраняется при переходе между вкладками, но сбрасывается для новой экспедиции. UI-тест проверяет выбор недостигнутого Суэца и стартовый Лондон на синтетических данных.
4. Assemble/unit/lint/release compile, instrumentation на эмуляторе, отдельное строгое ревью межмодульной интеграции, CI и автоматическое слияние. P02/F02/Q01 с настоящими шагами остаются на физическом телефоне.

Порядок: чистая модель детали → UI/доступность → тесты/эмулятор → строгое ревью → PR/CI/merge.
