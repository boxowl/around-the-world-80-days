# V2.3a — контракт/предложение точной привязки якорей «Пути» к измеренной геометрии

Статус: предложение для отдельной feature-задачи, 2026-10-09. Основание: решение владельца — для новых экспедиций единственный источник общего прогресса и финиша — измеренный `RouteDatasetV1` (D = 40 502 книжных км, k = 20, без дневного лимита, ~2025,1 реальных км до финиша). 28 строк владельца задают порядок остановок, сцены, исторический транспорт и героев; присланные километры — ориентир относительного ритма, НЕ точные пороги и НЕ отдельная сумма начисления. Несовпадение 2192,05/2343,60 и гипотеза 168,5→16,95 баланс не блокируют и не исправляются. Скрытого коэффициента нормализации нет. Выдуманных координат/порогов для спорных точек нет.

## Принцип привязки

Для каждого из 28 визуальных участков определяются два якоря (начало и конец). Якорь получает **детерминированное положение на измеренной геометрии** — книжные метры от старта, вычисленные из `RouteDatasetV1` (кумулятивная длина плеч до сопоставленного узла/точки на плече). Никаких километров из исходной таблицы владельца в порогах не используется. Позиции якорей производные от версии набора (`ROUTE_GEOMETRY_VERSION`): при смене версии пересчитываются той же функцией.

### Класс A — точка есть в наборе (порог выводим сразу)

Строки 2–11, 13–15, 17–18, 22–23, 25–28 (по матрице `docs/design/v23-anchor-matrix.md`): якорь = существующий узел (`london`, `dover`, …, `suez`, `kholby`, `allahabad`, `calcutta`, `singapore`, `hong-kong`, `shanghai-mouth`, `yokohama`, `san-francisco`, `omaha`, `chicago`, `queenstown`, `dublin`, `liverpool`, финальный `london`). Порог якоря = кумулятив книжных метров до узла по плечам набора. Для строк, покрывающих часть плеча (12, 16, 19–21, 24), — см. классы B/C.

### Класс B — точка в наборе как waypoint (нужна интерполяция на плече)

- **Бенарес** (`benares`, waypoint плеча `leg-11-allahabad-calcutta`): порог = кумулятив до начала плеча + дуговая доля waypoint на плече (детерминировано геометрией, без новых чисел).

### Класс C — точки владельца без однозначного узла (пробелы; НЕ выдумывать)

Для этих точек в контракт V2.3a входит только **вопрос привязки с источниками**, не сама привязка:

1. **Пеший пролог** (Дом №7 Севиль-роу → Реформ-клуб → вокзал): в наборе узлов нет. Варианты: (а) пролог только как сцена до `london`, порогов нет; (б) включить в набор версии 2 с координатами из источника (адреса известны: Севиль-роу, Реформ-клуб на Пэлл-Мэлл, вокзал) — требует версии набора и ревью. Решение — владельца.
2. **«Невада»/«Юта»** (строки 19–20): кандидаты из романа и линии 1869 г. — `reno`/`winnemucca` (waypoint) и `ogden`. Источники: график романа (Главы XXVI–XXXI), историческая линия Central/Union Pacific. Требуется выбор владельца из 2–3 компактных вариантов.
3. **«Ски-Камберленд»** (строки 21–22): не идентифицирован в романе и на линии 1869 г.; функционально — начало саней (романный Форт-Керни, `fort-kearney` есть в наборе). Варианты: (а) привязать к `fort-kearney` с сохранением отображаемого названия владельца; (б) оставить якорь без геометрического порога до уточнения. Решение — владельца.
4. **«Джерси»** (строки 24–25): исторически конец трансконтинентального поезда — Джерси-Сити напротив Манхэттена; роман и штамп — Нью-Йорк (`new-york` в наборе). Варианты: (а) якорь = `new-york`, «Джерси» — визуальная деталь сцены; (б) добавить waypoint Джерси-Сити в версию 2 набора. Решение — владельца.

### Класс D — спорные силуэты (без новых категорий)

- Океанские пакетботы (строки 7–9, 17, 18): единый силуэт «корабль-пакетбот»; «паром» остаётся только Дувр–Кале. Вариант с атлантическим торговым силуэтом для Henrietta (строка 25) — отдельно.
- Tankadere (строка 16): варианты — условный «пароход» с подписью «шхуна» в карточке или силуэт с парусами внутри категории «пароход»; 11-ю категорию не вводить автоматически.
- Суэцкий канал и река Хугли: продолжение силуэта соответствующего корабля.

## Контракт данных (для реализации)

- Новый файл `expedition/path/PathRouteV1.kt`: 28 участков — стабильные ID якорей, ссылка на ID узла `RouteDatasetV1` (класс A/B) или пометка пробела (класс C до решения), `historicalTransport`, присутствующие герои (Фогг/Паспарту/Ауда по утверждённому графику), `reward = NONE`, опциональная ссылка на сюжетную остановку/штамп из существующих правил (штампы не выдаются якорями).
- Пороги вычисляются функцией от набора, не хранятся литералами: `anchorBookMeters(anchorId, routeVersion)`.
- Тесты: каждая ссылка класса A/B существует в наборе; пороги монотонны; финиш 28-й строки = D; график героев непротиворечив; пробелы класса C явны и не имеют порогов.

## Критерии готовности V2.3a

- Все 28 строк получили класс A/B/C/D и либо детерминированный порог из геометрии, либо явный документированный пробел с вариантами и источниками.
- Ни одного числа из исходной таблицы владельца в порогах; ни одной выдуманной координаты; `RouteDatasetV1` не изменён (изменение набора — только версией 2 отдельной задачей с astra-review).
- Документ привязки обновлён фактическими порогами классов A/B; сборка, unit-тесты, lint зелёные; astra-review расчётов порогов; PR без автоматического слияния.
