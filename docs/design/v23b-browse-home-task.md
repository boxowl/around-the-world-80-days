# V2.3b · просмотр пройденного на экране «Путь»

Статус: реализовано в отдельной ветке `feature/v23b-browse-home` от `main` (`015b815`); ожидает проверки PR и решения о слиянии.

## Цель и зависимости

Подключить проверенный в PR #14 просмотр прошлой позиции к обычному экрану «Путь» для уже сохранённой экспедиции. Основание — `docs/design/v21-browse-proto.md`; художественный эталон двух фрагментов P08 принят владельцем 2026-10-29. Подтверждённая позиция по-прежнему приходит только из `FirstLegMapProjection` и сохранённых шагов.

## Границы

- Разрешены `JourneyHome.kt`, `SeamlessJourneyCanvas.kt`, чистые тесты browse, один UI-тест и эта заметка/`TODO.md`.
- Не менять Room, Health Connect, Expedition, пороги, данные дневника, навигацию, миграции, правила календаря и v2-геометрию.
- Просмотр остаётся визуальным: жест или действие доступности не меняют сохранённые шаги, открытую запись и подтверждённый прогресс.

## Критерии готовности

1. На экране «Путь» можно отмотать сцену назад, нельзя перейти в ещё не пройденный участок, можно вернуться к подтверждённой позиции; при отсутствии пройденного пути действие не предлагается.
2. В дереве доступности есть действия для предыдущей/следующей пройденной остановки и возврата. Описание сцены в режиме просмотра относится к просматриваемой позиции, тогда как числовые показатели страницы остаются подтверждёнными.
3. Повторная сверка, коррекция назад, reduced-motion и владение камерой сохраняют контракт PR #14.
4. Debug-сборка, unit, lint и UI-проверка на эмуляторе проходят; демонстрационные шаги помечены синтетическими. Физический телефон остаётся отдельной P02/F02/Q01 приёмкой.

План: прочитать v1 SPEC и прототип PR #14; подключить готовый рендер в `JourneyHome`; добавить доступные альтернативы жесту; проверить граничные случаи и UI; отдельно просмотреть пересечение с прогрессом и состояниями камеры перед PR.
