# P02: вчерашние шаги в диагностике Health Connect

Цель: дать испытателю отдельный итог за предыдущую календарную дату для HC11 (поздняя синхронизация), сохранив существующие «сегодня» и «7 дней». Это диагностическое чтение, не начисление экспедиции.

- Ветка/worktree: `feature/p02-yesterday-diagnostics`, `p02-yesterday-diagnostics/mobile` от `main`.
- Разрешённые файлы: `health/StepDiagnostics.kt`, `health/DiagnosticsScreen.kt`, `StepDiagnosticsTest.kt`, этот документ, `docs/HEALTH_CONNECT_TEST.md`, `TODO.md` и `docs/screenshots/p02-yesterday-diagnostic.png`.
- Не менять: `HealthConnectStepsGateway`, набор разрешений, Room, `ExpeditionSync`, календарь экспедиции, маршрут, v2 и код иных экранов.
- Зависимости: существующий `StepsGateway.aggregate(ReadWindow)` и разрешение `READ_STEPS`; телефон для реализации не требуется, аппаратная P02 остаётся открытой.
- Правило: «вчера» — от полуночи предыдущей даты до полуночи текущей даты в текущем диагностическом поясе телефона. Отсутствие записей (`null`) не превращать в 0. Повторное чтение заменяет показания; ошибка, отзыв разрешения и отмена чтения сохраняют текущие защитные состояния.
- Границы `TimeRangeFilter.between` — начало включительно, конец исключительно по [документации Android](https://developer.android.com/reference/androidx/health/connect/client/time/TimeRangeFilter). Поэтому чтение «вчера» заканчивается ровно на начале «сегодня», без двойного включения полуночи.
- Готово: экран показывает дату и итог вчера отдельно от сегодня и 7 дней; тесты покрывают границы календарных дат и DST, позднее исправление вчера без прироста сегодня, `null` против 0, отзыв разрешения и ошибки; `assembleDebug`, unit-тесты и lint проходят. Проводится отдельное строгое ревью окон, разрешения и отсутствия влияния на игровой прогресс. Физический телефон проверяется позже по `docs/HEALTH_CONNECT_TEST.md`.

План: изучить текущую диагностику и HC11 → добавить один диагностический запрос и строку UI → проверить тесты/сборку/lint и границы изменений → открыть PR без слияния.

Скриншот `docs/screenshots/p02-yesterday-diagnostic.png` снят на Android 16 эмуляторе после выдачи тестового доступа. На нём нет записей Steps: обе строки честно показывают «нет данных»; он подтверждает только компоновку интерфейса, а не работу реального источника.

Итоговое ревью: новый запрос остаётся внутри `StepDiagnostics` и использует прежний gateway/`READ_STEPS`; игровая сверка и Room не менялись. Интервалы смежные и полуоткрытые, проверены тестом для 23-часового дня перехода на летнее время. После всех трёх агрегатов разрешение проверяется повторно; ошибка третьего запроса не отдаёт частичный снимок. `assembleDebug`, 95/95 unit-тестов и lint без ошибок прошли; на эмуляторе 7 instrumentation-тестов прошли, 4 существующих UI-теста пропущены по их явному условию `syntheticSeed=allow`, не переданному в этот запуск. Физический телефон не подключался.
