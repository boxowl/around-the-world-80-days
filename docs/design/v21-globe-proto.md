# V21 — прототип вращаемого глобуса (debug)

Статус: debug-прототип для программы V2 (см. `KIMI_AROUND_THE_WORLD_V2_PROMPT.md`, §5
«Вкладка Карта» и §8). Не интегрируется в пользовательский UI, живёт только в
`app/src/debug/`, запускается явным интентом. Маршрут и позиция героя — **тестовые
данные**, не продуктовый контракт.

Запуск демо:

```sh
adb shell am start -n com.boxowl.aroundtheworld/.debug.globe.GlobeProtoActivity
```

## Подход

Собственный 2D-рендер сферы на Compose Canvas (без движков), ортографическая
проекция — §5 прямо допускает такое решение. Вся геометрия считается на единичных
3D-векторах, поэтому антимеридиан (±180°) не является особым случаем ни для
береговых линий, ни для маршрута: сегменты интерполируются через slerp, а не через
долготу.

Файлы (`app/src/debug/java/com/boxowl/aroundtheworld/debug/globe/`):

- `GlobeMath.kt` — чистая математика без Android-зависимостей: вектора, проекция,
  видимость `cos c > 0`, кламп центра ±60°, slerp, клиппинг полилиний по
  горизонту, сшивка фрагментов полигонов по дуге горизонта.
- `CoastlineData.kt` — декодер бинарного ассета береговых линий сразу в 3D-векторы.
- `GlobeScene.kt` — построение кадра в Compose Path (независимо от DrawScope,
  поэтому те же проекции используются для hit testing).
- `RouteData.kt` — **тестовый** маршрут романа с морскими обходами, остановки,
  тестовая позиция героя (85% участка Порт-Саид → Суэц).
- `GlobeProtoActivity.kt` — жесты (drag с инерцией, pinch-зум), кнопка «к герою»,
  легенда транспорта, подписи остановок, тап по маркеру.

## Данные береговых линий

- Источник: **Natural Earth**, `ne_50m_land` (1:50m land polygons), GeoJSON из
  https://github.com/nvkelso/natural-earth-vector. Лицензия: **public domain**
  (https://www.naturalearthdata.com/about/terms-of-use/). См. также
  `app/src/debug/assets/ne_land.README.md`.
- Исходный GeoJSON (1.6 МБ) в Git не коммитится; регенерация:
  `python3 app/src/debug/tools/prepare_land.py ne_50m_land.geojson app/src/debug/assets/ne_land.bin 0.10`
- Пайплайн: отброс микро-островов (< 0.35°), упрощение Дугласа–Пекера 0.10°,
  принудительная ориентация колец (внешние CCW — важно для сшивки на горизонте),
  квантование 16 бит, дельта-кодирование zigzag-varint.
- Итог: `ne_land.bin`, **36.3 КБ** (616 полигонов, 11 031 точка) — в пределах
  целевых 80–250 КБ с большим запасом.

## Математика рендера

- Видимость точки: `dot(P, C) > 0`, где C — вектор центра вида (λ0, φ0).
- Проекция: `x = P·E`, `y = P·N` (E/N — местные восток/север в центре), диск
  радиуса R на экране.
- Клиппинг: полилиния режется посегментно; концы фрагментов лежат точно на
  горизонте (линейная интерполяция по `dot` с нормализацией). Обратная сторона
  отбрасывается.
- Заливка суши: фрагменты внешних колец сшиваются в замкнутые контуры дугами по
  краю диска — каждый конец фрагмента соединяется с началом следующего по углу
  против часовой (правило корректно для CCW-колец, проверено JVM-тестами с
  point-in-polygon по синтетическим континентам). Полностью видимые кольца
  добавляются как есть. Заливка even-odd поверх диска океана.
- Маршрут: slerp-уплотнение до ~1.5°, накопленная длина дуги; клиппинг тем же
  кодом; граница «пройдено/впереди» делит сегмент в произвольной точке (не по
  городам); пройденное — сплошной линией цвета транспорта, будущее — серым
  пунктиром (dash-эффект непрерывен внутри видимого фрагмента).

## Проверено на эмуляторе (Pixel 7 / Android 16)

- Общий вид: розоватая суша, светлый океан, тонкие сине-фиолетовые контуры,
  лёгкая градусная сетка — по направлению референса 80days.world.tilda.ws
  (собственный арт; графика Tilda не используется).
- Вращение drag'ом с инерцией и затуханием; полюса клампятся на ±60°;
  «к герою» плавно возвращает вид к тестовой позиции (Суэц).
- Обратная сторона: маркеры и маршрут корректно скрыты, сшивок на горизонте
  не видно.
- Область ±180° (вид на Тихий океан): дуга Иокогама → Сан-Франциско проходит
  через антимеридиан без шва; берега Чукотки/Аляски без артефактов.
- Тап по маркеру: имя остановки в нижней панели + кольцо выделения.
- JVM-тесты (`app/src/test/.../GlobeMathTest.kt`, 9 шт.): видимая/невидимая
  точка, кламп полюсов, slerp через ±180°, клиппинг на горизонте, сшивка одного
  и двух полигонов, декодирование ассета. `:app:testDebugUnitTest` зелёный,
  `lintDebug` чистый.

Скриншоты: [`v21-globe-europe.png`](../screenshots/v21-globe-europe.png) (Европа/Африка, герой у Суэца) и [`v21-globe-pacific.png`](../screenshots/v21-globe-pacific.png) (Тихий океан, антимеридиан). Видео вращения с инерцией: `dist/v21-globe-clean.mp4` (не в Git; записано 540x1200, просмотрено штабом).

## Ограничения прототипа

- Маршрут, остановки и позиция героя — ручные тестовые данные (`RouteData`),
  не связаны с `docs/ROUTE.md` и состоянием экспедиции.
- Морские обходы заданы ручными вспомогательными точками, а не вычислены;
  для прода нужен один географический набор маршрута (§5), согласованный со
  спецификацией V2.
- Каспий (единственная дырка в ne_50m_land) при пересечении горизонта может дать
  мелкий артефакт заливки на краю диска (дырки не сшиваются по дуге, закрываются
  хордой).
- Нет рельефа, границ 1872 года, карточек остановок, состояний «достигнуто»,
  связи с дневником — это следующие этапы V2.
- Подписи остановок с простым анти-коллизионным фильтром; без иерархии зума.
- Производительность не профилировалась: пересчёт сцены каждый кадр вращения
  (~11k точек берегов + маршрут) — на эмуляторе вращение плавное, но перед
  прод-интеграцией проверить на слабом железе (minSdk 28).
- Кольца, полностью ушедшие за горизонт, не рисуются (случай «полигон покрывает
  весь видимый диск» для реальной суши невозможен, но код сознательно не
  обрабатывает).

## Что нужно для прод-интеграции

1. Единый географический набор маршрута V2 (узлы, транспорт, пороги) в общем
   модуле, согласование с литературным маршрутом и балансом (§8).
2. Перенос рендера из debug в main: `GlobeMath`/`GlobeScene` практически без
   изменений (Android-зависимостей нет), ассет — в `main/assets` (решить,
   достаточно ли 36 КБ 50m или нужен 110m для стиля).
3. Источник позиции героя и состояний остановок из модели экспедиции (Room),
   включая корректировки назад (цвет пройденного считается по книжной позиции).
4. Карточки остановок, связь с записями дневника, блокировки будущих остановок.
5. Инструментальный контроль качества: тесты на физическом устройстве (P02/Q01),
   проверка 60 fps на слабом железе, тёмная тема (сейчас только светлая
   «атласная» палитра).
