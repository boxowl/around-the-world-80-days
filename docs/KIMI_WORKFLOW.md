# Работа проекта в Kimi Code

## Структура

Главная Kimi-сессия workspace `mobile` используется как штаб. В ней принимаются продуктовые и архитектурные решения, выбирается следующая задача и принимаются результаты. Самостоятельная фича выполняется в отдельной верхнеуровневой сессии и отдельном Git worktree.

Кастомные субагенты проекта находятся в `.kimi-code/agents/`:

| Агент | Назначение | Может менять файлы |
|---|---|---|
| `terra-research` | Исследование и диагностика | Нет |
| `sol-implementation` | Реализация фичи | Да, в границах задачи |
| `astra-review` | Строгое интеграционное ревью | Нет |
| `luna-mechanical` | Малые механические правки | Да, только узкие правки |

Kimi может выбирать агента автоматически по описанию. Можно указать его явно в сообщении: «Используй `terra-research`, чтобы исследовать…» или «После реализации вызови `astra-review`».

## Ограничение модели Kimi

Субагент работает внутри текущей сессии в изолированном контексте и возвращает итог родителю. Он не создаёт отдельный видимый пользовательский чат. Для долгой самостоятельной фичи, собственного worktree и отдельной истории создавайте новую верхнеуровневую сессию Kimi вручную.

Не запускайте параллельно двух пишущих агентов в одном worktree. Максимум два одновременных субагента; безопасный параллелизм — независимые исследования или ревью.

## Шаблон первого сообщения feature-сессии

```text
Цель:
Границы: какие модули/файлы можно менять.
Не трогать:
Зависимости от других задач:
Критерии готовности:
Ветка/worktree:
План агентов: кто исследует, кто реализует, кто ревьюит.
```

## Цикл

1. Штаб выбирает отдельный проверяемый результат.
2. Создаётся ветка/worktree и feature-сессия.
3. `terra-research` возвращает карту контрактов и рисков.
4. `sol-implementation` реализует и проверяет.
5. Для сложных частей `astra-review` делает независимое ревью.
6. Создаётся PR без самостоятельного слияния.
7. Штаб проверяет CI, принимает PR и обновляет `TODO.md`.
