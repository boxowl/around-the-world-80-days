# V2.2e — календарь пари v2

Старт: 2026-11-12. Ветка `feature/v22e-v2-calendar`, worktree `/private/tmp/mobile-v22e-v2-calendar`, база `4f15478`. Источники: `docs/SPEC.md`, `docs/design/v2-product-decisions.md`, `Expedition.kt`, `CreditLedger.kt`, `V2CreditRepository.kt`.

## Цель

На пользовательском экране активной v2-экспедиции показать календарный день, срок и исход пари по сохранённым данным. В свободном режиме срока и победы в пари нет. Поздняя корректировка дневных данных пересчитывает исход без потери пути.

## Границы

Разрешены новая чистая модель `expedition/credit/V2WagerCalendar.kt`, её JVM-тесты, точечный вывод в `V2JourneyScreen.kt`, эта задача и `TODO.md`. Не менять Room/DAO/миграции, Health Connect, `V2CreditRepository`, `CreditLedger`, геометрию, паспорт, v1-календарь, графику и Gradle.

## Критерии готовности

1. В поясе, сохранённом при старте: день 1 начинается в момент старта и заканчивается в ближайшую полночь; дедлайн — полночь после 80-й календарной даты. Различие DST и системного пояса покрыто тестами.
2. Пари: книжные метры только дат в 80-дневном окне, точный итог из целых подтверждённых метров и k=20 один раз. Цель — утверждённые D = 40 502 000 книжных метров. Победа имеет приоритет над истечением при поздней корректировке дней внутри окна. Шаги после окна продолжают путь, но не выигрывают пари.
3. UI честно показывает текущий календарный день, дату срока в фиксированном поясе, состояние пари и отдельно общий книжный прогресс. При неизвестных днях не обещать, что шагов не было.
4. JVM boundary-тесты, assemble/unit/lint, эмуляторный UI-сценарий и отдельное строгое ревью календаря/арифметики перед PR и автоматическим слиянием. Физические P02/F02/Q01 остаются открыты.

Порядок: проверить контракт дат/порога → чистая модель и тесты → UI → независимое строгое ревью → эмулятор/CI → PR и слияние.
