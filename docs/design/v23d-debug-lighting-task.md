# V2.3d — освещение синтетического debug-глобуса

Старт: 2026-11-11. Ветка `feature/v23d-debug-lighting`, worktree `/private/tmp/mobile-v23d-debug-lighting`, база `3bd0ec4` (PR #28 уже в main).

## Цель и границы

Показать на синтетическом debug-глобусе цикл `DistanceLighting` по отображаемым расчётным реальным километрам. Разрешены `app/src/debug/java/com/boxowl/aroundtheworld/debug/globe/GlobeSliceActivity.kt`, его существующие тесты или новый тест для debug-проекции, этот документ и `TODO.md`. Не менять модель освещения, начисление, Room, Health Connect, production UI, маршрут, пороги и графические ассеты.

## Критерии готовности

1. Затемнение на глобусе вычисляется из `ledger.totalRealMeters / 1000.0`, а не из книжного расстояния или времени устройства. В диагностике указаны расчётные километры и фаза освещения.
2. Сценарии по обе стороны 20 и 30 км визуально различимы; повторное открытие и переход между сценариями пересчитывают освещение без накопленного состояния.
3. Синтетический баннер и подписи остаются читаемыми. `assembleDebug`, unit и lint проходят, проверка на эмуляторе документирована. Это не подтверждает реальные шаги P02/F02/Q01.

Порядок: подключить модель к debug Canvas → проверить сценарии и контраст → локальные проверки → PR → обновить TODO с результатом и следующим блоком.

## Проверка 2026-11-11

На Android 16 эмуляторе установлена debug-сборка из этой ветки. Синтетические `meters_today=10000` и `25000` дали соответственно светлую и тёмную карту; повторный `am start` передал новый intent уже запущенной Activity и пересчитал состояние. Первый снимок тёмной фазы выявил белые подписи за краем глобуса на светлом фоне; добавлена тёмная обводка, после чего подписи читаются и на глобусе, и снаружи. Снимки для локальной проверки: `/private/tmp/v23d-light.png`, `/private/tmp/v23d-dark-final.png` (не входят в Git). `:app:assembleDebug`, `:app:testDebugUnitTest`, `:app:lintDebug` прошли. Проверка синтетическая; реальное поступление шагов не утверждается.
