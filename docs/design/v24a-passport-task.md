# V2.4a — постановка: доменная модель паспорта путешественника (read-only, для проверки штабом)

Дата: 2026-10-11. Это постановка для проверки штабом, НЕ начало реализации. Код не писать, feature-сессию не создавать до подтверждения. PR #17 открыт и не слит; PR #12/#14 не сливать.

## Цель

Доменная модель паспорта: **ровно 9 отметок** по утверждённым правилам — стартовая отметка Лондона + 8 штампов финишей глав (Суэц, Бомбей, Калькутта, Гонконг, Иокогама, Сан-Франциско, Нью-Йорк, Лондон-финал). Ключевой инвариант: **полученный штамп не отзывается** — при отрицательной корректировке прогресса, поздней замене данных и повторном пересечении порога переданный набор штампов сохраняется и не дублируется. Модель чистая, без UI и без хранения.

**Контракт чистой модели (исправлено по ревью штаба 2026-10-11):**

- Явный вход: `PassportSnapshot(granted: Map<StampId, Instant?>)` — ранее выданные штампы с датами (null = дата неизвестна). V2.4a НЕ сохраняет и НЕ восстанавливает штампы сама: хранение, восстановление после перезапуска и миграция — критерии отдельной V2.4b и в V2.4a проверенными не заявляются.
- Монотонная операция: `reconcile(existing: PassportSnapshot, totalBookMeters: Long, observedAt: Instant? = null): PassportSnapshot` — результат = объединение переданного набора и штампов, пороги которых достигнуты; переданный набор никогда не уменьшается (union), даты переданных штампов не переписываются.
- Дата выдачи: для нового пересечения сохраняется переданное `observedAt`; если дата неизвестна — `null`. Задним числом из одного текущего итога дату не выводить. Backfill исторических дат и источник календаря — V2.4b.
- Стартовый и финальный Лондон — **разные стабильные StampId** при одном геометрическом nodeId (`london`): `stamp-london-start` (порог 0) и `stamp-london-finish` (порог = D).
- Пороги остальных 7 финишей глав — кумулятивы существующих концов плеч `RouteDatasetV1` (суэц = конец `leg-06b`, Бомбей — конец `leg-08`, Калькутта — конец `leg-11`, Гонконг — конец `leg-13`, Иокогама — конец `leg-15`, Сан-Франциско — конец `leg-16`, Нью-Йорк — конец `leg-20`), вычисляются функцией от набора, не литералами. Визуальные якоря PR #17 (`path/**`) не использовать — паспорт опирается только на геометрию и книжные метры.

## Границы единиц (критично, по сигналу штаба 2026-10-11)

- `RouteMeasure`/кумулятивы плеч дают **уже книжные километры**. Порог паспорта в книжных метрах = `cumulativeBookKm × 1000`. **Никакого ×20 в паспортном модуле**: k=20 применяется ровно один раз — в `CreditLedger.totalBookMeters` (реальные метры → книжные). Повторное применение k к кумулятивам геометрии — ошибка (уже отклонена штабом дважды в скрипте subagent agent-26).
- Финиш: `stamp-london-finish` = `totalKm() × 1000` книжных метров (D ≈ 40 502 км → ~40 502 000 м); старт = 0. Сравнение прогресса идёт против `totalBookMeters` из CreditLedger без дополнительных множителей.
- Astra-review обязан явно проверить все 9 порогов против `RouteMeasure` и `CreditLedger`, особенно финиш, на отсутствие ×20 / ×20 000.

## Критерии готовности

- Модель покрывает ровно 9 отметок; `stamp-london-start` (порог 0) и `stamp-london-finish` (порог = D) — разные ID при одном nodeId; остальные 7 порогов — кумулятивы концов плеч, проверены тестом против `RouteMeasure` (не литералы).
- `reconcile` монотонен: результат ⊇ переданного набора; при скачке через несколько глав выдаются все положенные; повторный вызов с теми же аргументами идемпотентен; корректировка прогресса вниз НЕ отзывает переданные штампы (union); даты переданных штампов не переписываются.
- Новое пересечение получает переданное `observedAt`; без даты — `null`; заднего числа нет. Тесты: пустой вход, частично выданный набор, скачок, откат, повтор, идемпотентность.
- Стартовая отметка выдаётся при нулевом прогрессе v2 (порог 0).
- Старые экспедиции v1 не затрагиваются: модель не читает и не меняет их данные.
- Сборка/unit-тесты/lint зелёные; PR без автоматического слияния.
- **Не критерии V2.4a (это V2.4b, не заявлять проверенными):** реальное хранение штампов, восстановление после перезапуска, backfill исторических дат, источник календаря, миграция БД, интеграция с экраном «Паспорт».
