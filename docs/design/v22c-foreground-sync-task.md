## Результат и границы

Добавить отдельный сервис foreground-сверки для активной v2-экспедиции: Health Connect `StepsRecord.COUNT_TOTAL` через существующий `StepsGateway` → заменяющие дневные шаги → `V2CreditRepository.reconcile`. Разрешены новый `expedition/credit/V2StepSync.kt`, его unit-тесты, при необходимости небольшой тестовый fake, этот документ и `TODO.md`. Не менять Room-схему, v1-синхронизацию, Health Connect permissions/gateway, UI/навигацию, маршрут, паспорт, баланс, Gradle и ассеты. Сервис пока не вызывается из production ViewModel; это следующий блок.

## Критерии

1. Читает не более 120 дат (сегодня и 119 предыдущих) в фиксированном поясе экспедиции; первый день обрезает по `startedAt`, текущий по `now`. Более старые сохранённые дни не удаляются.
2. `null`/ошибка отдельного агрегата не превращаются в ноль. Явный `0` передаётся как замена. При отзыве разрешения или полном отказе чтения не вызывает запись. Повторная успешная сверка заменяет значение, не прибавляет.
3. Перед записью повторно проверяет разрешение; отклоняет время до старта и устаревший ответ. Передаёт `expeditionSeq`, чтобы репозиторий отверг ответ прежней попытки.
4. Unit-тесты покрывают окно, границу первой даты, пояс, неизвестный/нулевой день, частичные ошибки, отзыв доступа, stale и повторную сверку. Сборка, unit, lint и CI зелёные; отдельное строгое ревью синхронизации. Эмулятор не закрывает P02/F02/Q01.

Порядок: read-only карта v1-сверки → отдельный сервис и unit → ревью → локальные проверки → PR/CI → слияние → передача следующей задачи: production ViewModel/UI v2 и запуск с настройкой длины шага.
